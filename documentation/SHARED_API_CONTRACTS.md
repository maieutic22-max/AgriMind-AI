## 1. Global Standard Data Formats

### 1.1 Identifiers (IDs)
All primary keys for entities that persist across modules must use standard **UUIDv4** strings.
- **Example:** `"c4a7e945-8f63-47a3-b9dc-2e8f1925b410"`
- **Rationale:** Prevents ID collisions across distributed modules, enables offline client-side ID generation (for PWA offline sync), and prevents enumeration attacks.

| Entity | Field Name | Type | Format | Example |
| :--- | :--- | :--- | :--- | :--- |
| User | `user_id` / `id` | String | UUIDv4 | `"7f23a109-bc3d-4c5e-8591-12f8a4e32101"` |
| Farm | `farm_id` / `id` | String | UUIDv4 | `"1a42b8e2-5678-4321-a1b2-c3d4e5f67890"` |
| Field / Plot | `field_id` / `plot_id` | String | UUIDv4 | `"d932e6a1-9012-4567-b890-123456789abc"` |
| Crop Cycle | `cycle_id` | String | UUIDv4 | `"e019b842-1111-4222-b333-abcdef123456"` |

### 1.2 Crop Identification
To prevent discrepancies between botanical names, common English names, and vernacular Indian languages, all crop references must use a canonical slug accompanied by standard localization keys.

```json
{
  "crop_id": "cotton",
  "crop_name_en": "Cotton",
  "crop_name_hi": "कपास",
  "botanical_name": "Gossypium hirsutum",
  "category": "Cash Crop",
  "season": "Kharif"
}
```

### 1.3 Geographic Coordinates & Farm Plot Geometry
All geographic locations and plot boundaries must follow the **WGS84** coordinate reference system (EPSG:4326) and standard **GeoJSON (RFC 7946)** geometry formats.

#### Point Location:
```json
{
  "latitude": 18.5204,
  "longitude": 73.8567,
  "altitude_meters": 560.5
}
```

#### Field Boundary Polygon (GeoJSON Polygon):
```json
{
  "type": "Polygon",
  "coordinates": [
    [
      [73.8560, 18.5200],
      [73.8580, 18.5200],
      [73.8580, 18.5220],
      [73.8560, 18.5220],
      [73.8560, 18.5200]
    ]
  ]
}
```

### 1.4 Timestamps
All timestamps must be transmitted in **ISO-8601 UTC** format ending with `Z`:
- **Format:** `YYYY-MM-DDTHH:MM:SSZ`
- **Example:** `"2026-11-19T18:30:00Z"`
- Dates without times must use `YYYY-MM-DD` (e.g., `"2026-06-15"`).

### 1.5 Currency & Financial Amounts
To prevent floating-point rounding errors in agricultural ledgers:
- Monetary amounts must be represented as **two-decimal numbers** or **integers in minor units** (paise).
- Default currency: `"INR"` (`₹`).

## 2. Standard API Response Envelopes

### 2.1 Standard Success Envelope
For standard endpoints returning structured data:

```json
{
  "status": "success",
  "data": { ... },
  "meta": {
    "timestamp": "2026-11-19T18:30:00Z",
    "version": "v1"
  }
}
```

### 2.2 Standard Error Response Envelope
Every error generated by FastAPI must return this standard envelope to simplify frontend error handling:

```json
{
  "status": "error",
  "error": {
    "code": "RESOURCE_NOT_FOUND",
    "message": "The requested farm plot with ID 'd932e6a1-9012-4567-b890-123456789abc' was not found.",
    "details": [
      {
        "field": "plot_id",
        "issue": "Invalid plot identifier or plot does not belong to the authenticated user."
      }
    ],
    "timestamp": "2026-11-19T18:30:00Z",
    "path": "/api/v1/plots/d932e6a1-9012-4567-b890-123456789abc"
  }
}
```

#### Standard Error Codes:
- `VALIDATION_ERROR` (HTTP 422)
- `AUTHENTICATION_REQUIRED` (HTTP 401)
- `PERMISSION_DENIED` (HTTP 403)
- `RESOURCE_NOT_FOUND` (HTTP 404)
- `CONFLICT` (HTTP 409)
- `EXTERNAL_SERVICE_ERROR` (HTTP 502)
- `INTERNAL_SERVER_ERROR` (HTTP 500)

## 6. Contract Change Management Workflow

To modify any contract in this document during Phase 2:

1. **Do not unilaterally change endpoint paths or request/response structures.**
2. Open a discussion or propose the change in `documentation/SHARED_API_CONTRACTS.md`.
3. Inform the owner of the generating module and the consumer of the client module.
4. Once agreed, update this document and increment the revision version.
